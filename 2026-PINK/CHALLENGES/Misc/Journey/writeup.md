# Journey (PINK, misc)

## Summary
Challenge **Journey** from the PINK CTF, misc category. Main technique: xor-cipher. The gogogo.journey file is a GB program that, when executed, writes the following program. Each step is a program in a different language that **is rewritten in the next language**. The complete chain: The last program (Emojicode) contains 33 blocks which each calculate a flag character by XOR with a constant mask (0x3F).

## Statement and artefacts
GB on a journey through time and languages with me! Perhaps you will learn something new!

- Original: `work/gogogo.journey` (74 933 929 B).
- `work/main.go` and `work/file.go` are **identical copies** of `gogogo.journey` (same md5 `41a53ca1c34604b4d76cfda6f61bc7c7`) — inheritance from a previous session, of no interest.
- All steps were performed in `work/journey_run/` so as not to touch the originals.
- Tools used: `gcc`, `python3`, `rustc`, `ruby` (3.2.2), `javac`/`java` (OpenJDK 17).
- No network access required.

## Resolution method
1. **GB — gogogo.journey -> standard.journey**

The file is **GB** (`package main`). It contains a huge hex constant `gogogo`, decodes it then applies `deByte` byte by byte:

```
b = (i*i + 31*i + 107) & 0xFF
t = (ct[i] - b) & 0xFF
u = (t * 13) & 0xFF
pt[i] = ror1(u)          // right rotation of 1 bit
```

The first 4 decoded bytes give the **big-endian** length of the payload; the rest is written in `standard.journey`. Message displayed:

> “This Google language is a bit unusual, maybe I should go back to the standard.journey”

`standard.journey` was already present in `work/` (generated by a previous execution); the rest starts from this file.

2. **C — standard.journey -> snake.journey**

Generated C program, with 72 `L0…L71` tables and a `line_de` function:

```
st = 0xC0FFEE00 ^ (li*0x9E3779B9) ^ n ^ (salt << 24)
st ^= st << 13 ; st ^= st >> 7
for each byte j:
  t  = ror3(in[j] - salt)
  k  = (xs32(st) ^ (li*131) ^ j) & 0xFF
  out[j] = (t ^ k) - ((j + li) & 0xFF)
```

Compilation + execution:

```bash
cp standard.journey journey_run/standard.c
cd journey_run
gcc -O0 -w -o decode standard.c && ./decode
```

Output: `snake.journey` (6 157 736 B). Message:

> “C is only one letter; less is faster, but I also want to fight snakes and see a child of C »

3. **Python — snake.journey -> rusted.journey**

Python program. `Q1` is a hex blob; decoding in **10 rounds**:

```
for r from 9 to 0:
    y = zlib.decompress(y)
    y = y XOR sha256(key + byte(r) + key)
```

where `key = bytes.fromhex(Q0)`. Then reading a BE32 length and writing the payload.

```bash
python3 snake.journey
```

Output: `rusted.journey` (3,747,445 B). Message:

> “Python is pretty slow, I am afraid my computer has rusted by now”

4. **Rust — rusted.journey -> classic.journey**

Rust program. `Z2` is a list of 63 hex strings (≈ 1.87 MB total). Decoding:

```
blob = concat(hex(Z2))
for i, b:
    mix = (i * 131) & 0xFF
    x   = b ^ mix ^ key[i % len(key)]     // key = "1337coffee"
    out = ror1(x)
```

Then length BE32 + payload.

```bash
rustc -O --crate-name journey_layer -o decode_rust rusted.journey
./decode_rust
```

Output: `classic.journey` (1 872 164 B). Message:

> “Now that I am all rusted up, I should use a classic again”

5. **Haskell — classic.journey -> coffee.journey**

Haskell program. The hex strings `zz` are concatenated, then:

- `r1`, `r6`, `r8` are identities (reverse.reverse, splitAt+append, xor 0);
- `r9` can remove 1 byte (condition `r2`, here **false**);
- `d4` shifts each byte: `out[i] = (in[i] - (i+1)) mod 256`;
- reading a BE32 length + payload.

The output name and message are XOR hex encoded `0xAA`.

```bash
python3 decode_classic.py     # reimplementation of Haskell pipeline
```

Output: `coffee.journey` (934 394 B). Message:

> “Haskell was exhausting, now I need some coffee first!” »

6. **Java — coffee.journey -> awake.journey**

Java program `CappuccinoJourney`:

- PBKDF2 password: `"espresso-beans-42"` (`barista()`), salt = base64(`latte`), **9541 iterations**, **256-bit key**, `PBKDF2WithHmacSHA256`;
- IV = base64(`espresso`) (12 bytes);
- AAD = output file name (`awake.journey`);
- encryption **AES/GCM/NoPadding**;
- the ciphertext is the concatenation of the fields `cappuccino_000` … `cappuccino_015` (sorted by name, via reflection); `cortado()` corrects a possible base64 prefix.

```bash
cp coffee.journey CappuccinoJourney.java
javac CappuccinoJourney.java && java CappuccinoJourney
```

Output: `awake.journey` (694 936 B). Message:

> “After so much coffee I feel wide awake; my brain is completely scrambled »

7. **Brainfuck — awake.journey -> Ruby (base64)**

`awake.journey` only contains `+`, `-` and `.` (no loop or pointer). The program therefore works on **a single cell**: simply accumulate the `+`/`-` and transmit the cell at each `.`:

```python
cell = 0
for ch in code:
    if ch == '+': cell = (cell + 1) & 0xFF
    elif ch == '-': cell = (cell - 1) & 0xFF
    elif ch == '.': out.append(cell)
```

The output contains:

> “Now I would like to mine rubies. But how? »

followed by a long **base64** which decodes to source **Ruby**.

8. **Ruby — healthy_food.journey**

The Ruby source decodes two blobs (`marrakesh`, `valparaiso`) with a `JRNYv2\0\0` header, then applies XOR/SHA-256/gzip layers, and writes the final file.

```bash
ruby ruby_layer.rb
```

Output: `healthy_food.journey` (205 416 B). Message:

> “I found a ruby in the mine!” But now I am really hungry for some grapes! »

10. **Pitfalls / lessons**

- The branches `z9`, `opq`, `crema`, `tallinn`, `phantom_branch` and the files `decoy.bin`, `ghost.bin`, `sidequest.bin`, `ristretto.bin` are **decoys**: false conditions, dead code.
- `cortado()` and `lungo()` in Java are only used to reconstruct base64; the real decoding is PBKDF2 + AES-GCM.
- `awake.journey` is **degenerate** Brainfuck (no `<>[]`): no need to install a full interpreter.
- The “journey” is deliberately long: each step remains simple, but you have to be methodical and not get lost in the voluminous data.
