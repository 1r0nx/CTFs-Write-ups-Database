# 0-Overflow (Pwny-CTF, pwn)

## Summary
Challenge **0-Overflow** from the Pwny-CTF CTF, pwn category. Main technique: format-string. Gets() = prohibited (no size limit) -> immediate overflow. Same as scanf("%s"), unbounded strcpy.

## Statement and artefacts
Can you pwn this problem? Look at the challenge.c and pwn writeup for hints!

Code (challenge.c):
  int main() {
      char name[40];
      uint64_t number = 0xdeadbeef;   // just AFTER name on the stack
      ...
      gets(name);                     // gets() = no size limit -> overflow
      if (number != 0xdeadbeef) print_flag();   // read and display flag.txt
      else "Try again"
  }

Build: gcc -O0 -fno-stack-protector (no canary). Binary PIE, unstripped.

**Provided files / artifacts:**
- `Makefile (file, 118 B)`
- `challenge (file, 19.0 KB)`
- `challenge_patched (file, 19.0 KB)`

## Recognition signals
- If we observe gets read without bound, think about writing > 40 bytes overflows name and overwrites number.
- Signal: It is enough that number ≠ 0xdeadbeef.
- If we observe Build -fno-stack-protector (no canary), thinking about nothing prevents overwriting.

## Resolution method
1. Fill `name` (40 bytes) + overwrite `number` with anything (≠ 0xdeadbeef).
   - Beware of **alignment padding**: `name[40]` can occupy 48 bytes on the stack → send ~48 bytes.
2. `print_flag()` reads `flag.txt` on the server side → `sigpwny{hmm_gets_seems_a_little_unsafe}`.

2. **Flaw**

```c
char name[40];
uint64_t number = 0xdeadbeef;   // just after name on the stack
gets(name);                     // gets() does NOT limit size -> overflow
if (number != 0xdeadbeef) print_flag();   // display flag.txt
```
`gets` read without bound → write > 40 bytes overflows `name` and **overwrites `number`**. It is enough that `number ≠ 0xdeadbeef`. Build `-fno-stack-protector` (no canary) → nothing prevents overwriting.

## Lessons and reusable patterns
- gets() = prohibited (no size limit) -> immediate overflow. Same as scanf("%s"), unbounded strcpy.
- Local variable “to be protected” just after a buffer = target of a targeted overflow (no need to go as far as RIP).
- No canary (-fno-stack-protector) -> direct overflow. With canary, you would first have to leak it.
- Find the exact offset: cyclic(200) sent, value at crash -> cyclic_find(...).
